## 交互层级与使用流程

**主要流程：Policy tags → Start analysis → 查看结果 → Result month。**

| 层级 | 控件 | 当前用途 |
|---|---|---|
| 主入口 | Policy tags | 选择分析关注点；紧凑下拉内支持多选 |
| 主入口 | Start analysis | 默认直接启动既有皇岗规则分析；API模式先初始化和审查，再启动模拟 |
| 辅助配置 | Configure | 选择引擎；规则参数入口；API的PDF、研究日期、步长及选区 |
| 结果筛选 | Result month | 读取已保存规则月份/后端实际返回日期；不启动新模拟、不改政策 |
| 辅助视图 | View options | 原流线播放、流线动效、对照模式及人群筛选；API没有客流字段时不提供这些控件 |
| 详细分析 | Analysis details | 原右面板中的结果、政策记录、解释和参数调整；默认收起 |
| 阅读说明 | Policy interpretation & sources | 原说明文字折叠，按需展开 |

原英语品牌、白模城市、青/金流线、案例、版本历史和渲染选项保持继承。桌面样式目标：右面板370→320px，底操作条最小高度123→76px，默认收起分析面板。窄屏操作条分两行，详细面板按需打开。以上尺寸是CSS设定，本轮未能通过实际浏览器测量/截图验收。

## 标签定义与模型边界

| tag ID | 界面标签 | 当前规则演示 | 分析关注点 |
|---|---|---|---|
| border-access | Port opening | 可选 | 通关时间、口岸启用与出行需求 |
| transport-capacity | Transport capacity | 可选 | 接驳容量和未满足需求 |
| information-reach | Information reach | 可选 | 信息触达和分群知晓假设 |
| housing-affordability | Housing | 暂不可选 | 需要住房/定居模型 |
| public-services | Public services | 暂不可选 | 需要教育、医疗和照护模型 |

这是**前端预设标签**，还不是知识库自动标注的结果，也不是从生产政策库动态读取的可用政策。规则演示中，标签控制分析关注点与说明，不关闭未选中的模型机制；模型仍是皇岗口岸既有规则。住房/公共服务只在团队API或明确的API测试模式中允许作为输入范围；实际效果仍由后端能力决定。

案例记录保留 `analysisTags`；切换案例和刷新恢复已保存的规则案例关注点。标签关注点与政策版本不是同一个概念：查看旧月份不创建政策修订；改参数仍按原版本机制保存，已有早期快照不被追溯重写。

## Start analysis 的具体行为

1. 没有已应用规则政策：用现有参数与生效月份创建首个版本并显示Impact。
2. 已有政策且未修改参数：显示当前月份分析，不重复写版本。
3. 修改参数：按选定生效月份应用修订；非法追溯修改由原规则拒绝。
4. API：校验PDF和时间范围 → 初始化 → 审查有来源的信息/假设 → 勾选 → Confirm & start analysis。按钮明确表示确认并启动；内部仍调用confirm后再调用simulate。
5. API重复查看已完成结果：不重复发送模拟创建请求。改标签必须重新初始化与确认。
6. 请求失败：显示错误或重试，不把规则结果伪装成API响应。

API返回图层暂时替代城市画面；切回规则演示恢复原城市场景。新图层标记为分析覆盖层，白模材质切换不抹掉其颜色。旧城市刷新不会覆盖API图层。

## API接入与标签参数

原 `sandbox/server.py` 增加同源 `/api/v3/*`，与原 `/api/state` 等接口共存。公开瓦片署名保留，底图只出现在Configure的折叠选区内。

提议的初始化metadata额外包含：

```json
{
  "policyScope": {
    "schema": "nm-policy-scope-v1",
    "tags": ["border-access", "information-reach"],
    "purpose": "policy-analysis"
  }
}
```

这是本轮提出的扩展字段，原Word没有标签字段定义。后端必须确认字段并实现标签到政策/agent的路由，不能据此宣称已经完成实际标签筛选。

真实团队服务尚未配置；在服务端设置 `V3_BACKEND_URL` 并重启原服务器后，可按已提出的V3规范联调。默认运行仍为原规则演示；Configure里的 API test 明确为合成数据，不读取PDF正文、不调用LLM。
