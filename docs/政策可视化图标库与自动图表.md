# 政策可视化图标库与自动图表

2026-10-15（香港时间）。继续原位修改8893英文界面，不创建新的前端版本目录。此前八项入口、样式、覆盖层和测试文件保存在 `.history/2026-10-15-before-policy-visuals/`。

## 1. 原图示为什么不明显

住房和学位都以细小金色圆柱表示，缺少形状区分；投用前只有灰框，难以识别政策类别。原住房/学位折线只有280×88的微型画布，缺少数值轴与当前值；图表位于较长解读之后，分析完成后不易看见。颜色还承担了过多含义。

本轮采用“**类别靠图标和文字，数据状态靠颜色与线型，数量靠图表及单位**”。图表放到Impact顶部；六段标准化解读保留在其后。

## 2. 15种语义图标

[图标库总览](visual-library/catalogue.svg)是独立SVG资产，不是网站截图。[SVG符号库](visual-library/policy-icons.svg)可供设计或前端复用；页面Visual key可展开查看名称与定义。

| 图标key | 含义 | 不应混淆为 |
| --- | --- | --- |
| population | 某时点居民人口存量 | 跨境人次或迁移人数 |
| migration | 居住地迁入、迁出 | 一般出行流量 |
| inflow / outflow | 有时间和地区口径的流入/流出 | 自动推定的定居选择 |
| housing | 可用住房容量 | 实际楼栋数、入住人数、负担能力 |
| construction | 施工计划与累计交付 | 已启用设施或交通效益 |
| transport | 客运出行 | 唯一人口或净迁移 |
| rail / road | 铁路/道路资产及项目 | 新建里程、施工完成度 |
| capacity | 容量与约束 | 居民需求或满意度 |
| education | 学位需求与容量 | 实际学校建筑、保证入学 |
| healthcare / care | 医疗及照护服务类别 | 已存在相应模型或实测等候时间 |
| information | 信息与证据 | 决策概率、可信度分数 |
| jobs | 岗位存量或容量 | 政策新增就业成果 |

图标采用24单位矢量网格、统一线宽与端点。装饰图标不进入键盘焦点，按钮保留文字；独立图标带可访问名称。五类政策标签也加入相应图标。

共享数据颜色：青色＝无政策基线，金色＝政策情景/已投用量，灰色＝返回或计划背景，浅色点线＝需求，珊瑚色＝未满足需求。图例同时给出文字及线型；相同角色的多条线再用不同虚线与点形区分，避免只靠颜色辨认。

## 3. 分析后自动生成哪些图

| 当前数据/模型 | 自动生成的图 | 数据边界 |
| --- | --- | --- |
| 皇岗出行 | 所选客群月度基线/政策趋势、当前月出入境堆叠、全乘客接驳容量约束 | 单位是passenger trips/day；不是居民迁移 |
| 古洞北住房 | 需求与可用供给趋势、基线/政策缺口、当前有效版本的已投用与剩余量 | 家庭/可用住房容量；输入仍为假设 |
| 洪水桥学位 | 学生需求与学位趋势、缺口对照、学位投用进度 | 学生/学位；不包含其他公共服务模型 |
| API快照 | 有数值才绘制片区人口、岗位、路段拥堵原始值 | 无基线不推断增益；原始指数不转为百分比 |

| 交通建设 | 当前显示缺数据；提供计划/累计完成里程及剩余工程图模板 | 必须接项目、日期、状态与km；道路要素数量不能替代里程 |

## 4. 3D地图也使用可识别符号

住房改为高方体容量符号，学校改为宽低体块，加入类别图标牌、深色轮廓和底边参照。它们仍是容量符号，不是实际设施位置或真实建筑模型。

- 住房每个完整符号代表250套；学位每个完整符号代表100学位；尾块按比例显示。
- 全月份使用固定尺度，最大数量仍为80/50；未按当月最大值放大。
- 未分析、等待投用和零新增分别标识，显示0 COMMISSIONED；没有已投用量时不用金色新增标识。
- 分析层继续绕过白模中性材质，颜色不会被整体白模切换抹掉。

另修正原客流地图的方向分配：基准和新增客流分别读取模型自己的出入境量。旧画面将基准方向占比复用给新增量，和新方向图会产生差异；现已统一，模型总量、路径、半径及箭头500人次刻度没有改动。

## 5. 图表阅读与导出规范

数值轴包含零；同一图中全部系列与研究月份使用共同尺度。切换所选月份只移动标记，不单独放大本月效果。零柱宽度为零，不画最低可见“假增量”；缺失值保留null、折线断开、表格显示Not provided。净迁移或原始拥堵允许合法负值，坐标跨零。

各图附Data & units数据表和Save SVG。SVG包含可见标题、单位、系列图例与来源说明；Export原JSON额外包含`charts`规格，与政策、月份、客群和`interpretation`一致。API没有当前快照时为null。大于10行的柱图只预览前10行，比例和完整表格仍使用全部数据；SVG导出该预览，完整数据请用JSON/表格核对。

[七个图表规格示例](validation/automatic-chart-examples.json)含15张实际生成的图表规格和两个缺数据情形，均为假设/契约测试，不是实测结果。

## 6. 队友如何接真实数据

`policy-chart-model.js`生成纯JSON规格；`policy-charts.js`渲染SVG和表格；`policy-visuals.js`管理语义图标。现有模型在结果渲染时自动调用，不需要另按生成图表按钮。

迁移数据使用 [空模板](visual-library/residential-migration.template.json)：`nm-residential-migration-v1`，按月、persons、areaId、source；每条记录有date、observed/modelled状态及非负整数或null的inflow/outflow。只有两项均有值才计算net；净迁移不等于人口总变化。

建设数据使用 [空模板](visual-library/transport-construction.template.json)：`nm-transport-construction-v1`，按月、km、projectId、areaId、source；每条记录有date、planned/under_construction/completed状态、plannedKm及completedKm。累计完成量不得倒退或超计划，完成状态必须足量；缺失完成量不补零。

两个模板默认unavailable，不含假数据。拿到有效数据后调用`buildMigrationCharts(dataset)`或`buildConstructionCharts(dataset)`，再交统一renderer。当前V3团队契约未含这些字段，本轮没有假称已自动联上后端或另加上传入口。
