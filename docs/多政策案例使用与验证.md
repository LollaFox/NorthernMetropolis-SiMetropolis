## 2. 第一次查看住房结果

1. 刷新原 8893 标签页，Study area 选 **Kwu Tung North**。
2. Housing 标签和对应住房政策会自动选中；点击 **Start analysis**。
3. 在右侧 Impact 查看需求、供给与缺口。首次月份为 2026 年 8 月，此时尚未交付，新增量为零。
4. 点击 **Jump to Feb 2027 commissioning**，查看首次分期交付；也可使用底部 **Result month** 查看任一结果月。
5. 默认新增 1,600 套，2027 年 2 月起分四个月交付。2 月累计 400 套，5 月累计 1,600 套；7 月模拟需求 12,440 户，可用供给 12,600 套，缺口为零。

这些月份、数量和增长率是用于测试的假设，不是古洞北已核实的交付计划。金色方块每个代表 250 套，尾块按比例显示；不代表真实楼栋或选址。

## 3. 查看公共服务结果

1. Study area 选 **Hung Shui Kiu**，自动选择 Public services 与学位政策。
2. 点击 **Start analysis**；使用 **Jump to Sep 2027 commissioning** 查看新增学位。
3. 默认 2027 年 9 月一次增加 900 个学位：当月需求 3,730 人、供给 3,900 学位、缺口为零。
4. 金色方块每个代表 100 学位。容量覆盖不等于服务半径、学区分配或保证入学。

当前 Public services 是教育试点的外壳。接医疗或照护时，应增加对应政策、模型、计量单位和数据契约，不能复用学位公式并只换名称。

## 4. 调整政策与比较方案

| 操作 | 如何做 | 对历史的影响 |
| --- | --- | --- |
| 查看别月 | Result month | 只读取快照，不创建政策版本 |
| 修改假设 | Configure，修改新增容量、投用月份、分期月数、生效月份和原因；Save settings 后再 Start analysis | Save 仅为草稿；Start 才应用 |
| 重复分析 | 参数未变时再次 Start analysis | 复用结果，不重复写版本 |
| 从未来调整 | 已应用后选择不早于最新修订的生效月份，设置该月或以后的投用安排，再分析 | 保留生效月以前结果；同月修订留痕 |
| 保留已交付量 | 新计划总容量不得低于生效月以前已投用容量 | 已投用容量不被撤销；剩余量按新计划交付 |
| 改初始人口、需求、供给或研究窗口 | Analysis details → New case，再 Configure 中展开基线字段 | 首次应用后基线锁定；新案例保留原案例 |
| 切换方案 | Research case 选择已有案例 | 每例独立保存参数、历史和查看月份 |
| 分享结果 | Export | 导出当前专题完整计算结果；不是可重新导入的案例包 |

住房和教育保存在独立的 `nm-topic-scenarios-v1`；原皇岗的两项存储 key 未改。专题最多共 40 个案例。浏览器无法读取原存档时保留原数据，在内存中运行并提示导出；浏览器存储不等于团队共享数据库。

## 5. 计算与可视化口径

模型按月计算：需求＝初始需求＋每月变化；供给＝基线供给＋累计投用；缺口＝需求减供给，最低为零。新增容量从设定投用月起分期累加，按整数取整；未到投用月不会产生容量。政策改善最多等于当月无政策缺口，不把“新增 900 学位”直接等同“改善 900 人”。零需求时覆盖率显示不可用，不伪造百分比。

青色折线为无政策缺口，金色折线为政策后缺口，共用同一纵轴比例，越低表示缺口越少。灰色示意框表示研究位置；金色容量符号只在已投用后出现。白模外观切换不会抹掉分析颜色。原皇岗仍使用原流线和单位，住房/教育不复用客流数字。

Model 页展示确定性计算链路，明确没有调用 LLM。前端政策标签为人工预设种子，尚未接知识库自动标注系统。
