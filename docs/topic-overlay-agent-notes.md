# Topic overlay integration

`TopicOverlay(city)` owns a dedicated `THREE.Group` on `city.scene`. Instantiate once; call `show(policy, snapshot)` for a housing or education snapshot, `show(policy)` for a planned outline, `hide()` when returning to the port/API view, and `dispose()` during owner cleanup. Camera movement remains the caller's responsibility. `show` accepts catalogue policy objects; a snapshot needs an integer `delivered`, optional matching `policyId` and `model`, and an optional `date` label.

Locations resolve `getArea(policy.areaId).districtId` against existing `DISTRICTS`, without writing to world, policy ledger, capacity calculations or the camera. A dashed grey rectangle is a schematic study envelope, never a real policy polygon or catchment. Gold capacity symbols only appear when commissioned capacity is positive. One full housing glyph represents 250 units (maximum 80); one full education glyph represents 100 school places (maximum 50). The final glyph uses proportional height for partial capacity. Above-limit or fractional capacity values are rejected instead of silently clipping symbols. Labels retain the exact quantity and explicitly identify hypothetical assumptions and schematic placement.

The group's `userData.policyOverlay` flag excludes its symbols from the existing `WhiteModel` neutralization. All meshes share only resources owned by this overlay; repeated `show` disposes previous geometries, materials and canvas textures exactly once. `hide` clears only topic-specific canvas metadata; it retains geometry for visibility toggling until the next `show` or `dispose`.

Canvas datasets for read-only inspection: `topicPolicy`, `topicArea`, `topicModel`, `topicDelivered`, `topicGlyphs`, `topicDate`, `topicOverlay` (`planned` / `analysed`). Group metadata also retains the complete annotation text and glyph count. These are presentation metadata, not analysis state.

Automated verification: Node tests use real Three.js scene objects with a stub 2D label canvas, requiring no GPU. Coverage includes zero/scheduled capacity, separate district positioning, no camera/world mutation, full and partial glyph quantities, maximum quantities, comparable scales across months, resource ownership and disposal, hide/show metadata, invalid snapshot rejection, and white-mode refresh protection. No browser visual acceptance was performed by this agent because browser access was previously denied; the integration owner must state that limit.
