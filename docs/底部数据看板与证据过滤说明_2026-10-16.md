# 底部数据看板与证据过滤说明

版本：**H3-bottom-dashboard-2026-10-16**。在原英文 H3 界面内修改，沿用白模、政策标签、分析历史、API 和月份回放。

预览：<http://127.0.0.1:8893/>，刷新原标签页。项目根目录双击 `start.command` 可启动。

## 1. 使用流程

1. **Analysis sandbox**：依次选择 Study area、Policy tags、Matching policy；需要调整参数时进入 **Configure**，然后 **Start analysis**。
2. 分析完成后进入结果状态，默认收起浮窗，底部直接显示关键指标与一张可切换的统计图。已保存结果也可从右上 **Analysis history → Open results** 打开。
3. **Result month** 切月；后端保存城市还支持 **← / ▶ / →**。数字、环比、图中月份标记与城市保存状态同步。这里的环比是“相对上一个保存月”，不是政策带来的净收益。
4. 通过 **Chart** 选择住房、就业、建设阶段等图表。**Data & units** 展开完整数表；大数字用缩写展示，悬停或辅助阅读可获得完整值。
5. **Evidence ↗** 打开精简浮窗，核查机制、支持范围、局限和对象详情。**Export study** 仍导出原始研究/后端 canonical 数据。
6. 回到 **Analysis sandbox** 可继续配置；历史不会因此消失。原 **Map appearance、Settings、Help** 的分工保持不变。

本地皇岗/住房/学位模型：**Configure → Analysis engine → Local rule demo**。不再额外堆叠一个 Local demos 按钮。

## 2. 哪些数据直接放在底部

按当前引擎提供的字段选择，不把不同模型的指标混成一个城市总分。

| 分析来源 | 四个重点指标 | 统计图 | 需要保留的口径 |
| --- | --- | --- | --- |
| 后端保存城市 | 模型居民数、可用居民容量、已填岗位、已完成开发对象 | 居民/容量、提供/已填/空缺岗位、逐月建设阶段、可选模型满意度 | 居民容量单位是 resident places，不是住宅套数；对象可能是开发簇，不是单栋楼 |
| 住房案例 | 家庭住房需求、可用住房供应、未满足需求、累计投用新增供应 | 供需趋势、缺口趋势、当前投用进度 | 需求按 households，供应按 housing units；当前为假设模型 |
| 学位案例 | 适龄学生需求、可用学位、未满足需求、累计投用新增学位 | 供需趋势、缺口趋势、当前投用进度 | pupils 与 school places 区分；学校案例不能代表所有公共服务 |
| 皇岗案例 | 无开通基线、开通情景、额外出行、全体旅客未满足新增需求 | 所选出行目的趋势、方向分配、共享容量 | trips/day 不是独立人数或迁移人数；前三项随出行目的变化，第四项始终是全体旅客 |
| 通用 API 快照 | 已返回片区数；城市唯一人口和政策新增岗位明确显示未提供 | 返回的片区人口/岗位、原始拥堵指数 | 未解决片区重叠不能加总唯一人口；原始指数不能当作百分比 |

缺失数值显示 **— / Not provided**，真实 0 保持为 0。无上一保存月或上一值缺失时，不编造增长值。

趋势图使用整段保存期的共同纵轴。切月只改变选中标记，不逐月放大刻度。非趋势图超过 5 条观察值时显示明确预览提示，完整数表保留全部观察值；较长条形图在固定高度区域内滚动。

底部不默认加入 Token 消耗、模型调用次数、多个重复人口总数或未经验证的满意度“提升”。调用成功次数放入折叠技术来源，它不能代表推演准确率。

## 3. 浮窗保留什么

默认保留三个短段落：

- **Mechanism**：哪条脚本或规则改变了哪些变量。
- **What this supports**：这些数据支持检查什么，例如选定月的保存状态、供需缺口。
- **What it does not prove**：没有反事实或观测结果时，不能证明真实政策收益。

假设和内容审查折叠在 **Assumptions & content review**。后端额外保留 **Selected object · saved details**：按持久对象 ID 和月份读取，对住宅显示居民与容量，对商业显示岗位，不给车站或公园补造住宅/就业指标。全城大数字和图表不再在浮窗重复。

## 4. Agent 内容如何筛选

本次实现的是**展示层证据筛选**，没有增加一个能够判断现实真假的模型。大模型自己给出的置信度或引用不能自动成为验证凭据。

| 内容情况 | 处理 |
| --- | --- |
| 空文本、重复内容、月份不符、对象超出范围 | 排除，不作为当前结果展示 |
| 结构化数字与保存字段不一致或非有限数字 | 排除，注明字段不一致 |
| 结构化数字匹配对应对象/月份的字段 | 只确认该模型字段匹配；仍不批准整句自由文本 |
| 假设、参数敏感度、预设响应 | 标为假设，不当作观测结果 |
| 声称“政策导致现实改善”，但没有独立因果验证 | 标为 unsupported，不进入主要结论 |
| 缺乏可核对字段的自由叙事 | withheld，保留在原始来源供追溯 |

原始导出不被过滤器改写。浮窗显示审查数量和原因，主要结论使用受控模板及明确字段；因此一句“人口为 20，所以政策必然带来繁荣”即便数字匹配，也不会整句通过。

后端当前生成的是自由叙事，未提供结构化论断的字段映射，因此其原文默认不进入主要结论。这不是把所有被收起的文字判为虚假。

真正验证政策影响，需要队友后续提供观测结果、可比基线/反事实、指标定义与来源记录。前端可据此展示证据等级；仅凭文字语气无法可靠判真伪。后端建设依然由政府 JSON 决定，PDF 和标签尚不会改写脚本。

## 5. 首屏底部与动态效果规范

| 项目 | 本次规范 |
| --- | --- |
| 输入区 | 左侧统一放片区、标签、匹配政策；右侧放 Start analysis、Configure 和运行状态 |
| 字号 | 输入和按钮 12px，注释/单位 11px；结果主数字桌面 27px，较窄界面 24px |
| 控件 | 主控件最小高度 34px，统一间距；避免各按钮自行挤占一行 |
| 空白区 | 主按钮附近增加 Tags → Configure → Analyze 的小箭头动效，明确标注 Workflow preview · illustrative |
| 动效含义 | 是工作流程示意，不代表模拟正在运行；运行中隐藏；减少动态效果偏好下停止动画 |
| 窄屏 | 指标保持 2×2；图表位于其下，内部滚动；流程示意隐藏 |
| 浮窗避让 | 根据底栏实际测量高度留出空间，避免固定旧高度遮挡结果；浮窗默认关闭 |

本次没有改变白模材质、政策流线数量、计算规则、地理坐标或历史存储格式。
