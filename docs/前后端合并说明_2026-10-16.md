## 2. 建议先看这个流程

| 操作 | 会发生什么 | 数据含义 |
| --- | --- | --- |
| 打开页面 / Saved city | 显示后端首个保存月份及结果面板 | 默认21个月离线区域示例 |
| SAVED BACKEND RUN | 切换已有方案 | 读取保存状态，不重跑模型 |
| Result month / Result date | 地图、图表、指标和对象详情跟随日期 | 日期使用后端精确sourceDate；季度快照之间的保存月份也可查看 |
| 点击城市对象 → Saved object details | 按对象id和日期显示施工阶段及容量/入住/岗位 | 不通过显示名称猜测或拼接对象 |

图表包括人口与可入住容量、提供/已填/空缺岗位、当前建设阶段，以及有值时的合成满意度。每图有单位、数据表与SVG导出。解读分为范围、比较、机制、时间、证据限制、下一步验证六部分。

## 3. 要新建一次后端分析

1. 在Saved city点击 **New Team API analysis**，或从Configure选择 **Team API**。
2. 上传PDF并设日期/步长；完整区域脚本可选 `2025-01-01` 至 `2026-09-01`，Month。
3. Save settings后点击Start analysis，阅读初始化审查内容，勾选确认后执行。
4. 页面显示任务状态、已保存月份及返回的provider执行指标。完成后选择Result month。
5. Stop waiting只停止前端等待，**不取消后端任务**。Resume task恢复同一任务；刷新后不会自动重复提交。已知job使用GET恢复，重试保留operation key。

**当前后端不会解读PDF正文。** 它只核验PDF格式、保存摘要/文件信息；建设位置、类型和完成时间由服务启动时载入的政府JSON决定。前端政策标签是请求背景，不会自动改写建设计划。审查确认步骤会明确说明这一点。

因此，选择Housing标签并上传住房政策PDF，不能被理解为后端已经分析了该政策。要比较不同建设计划，请复制/修改 `backend/examples/northern-metropolis-scenario.json`，以 `--scenario` 代替 `--preset` 并使用新的数据目录启动；同一个数据目录只运行一个服务。字段与运行方法见 `backend/README.md`、`backend/docs/releases/FRONTEND_HANDOFF_ZH.md`。

## 5. 必须统一的指标口径

| 字段/展示 | 正确含义 | 不能替代 |
| --- | --- | --- |
| development cluster | 示意开发组团 | 真实单栋楼、真实地块 |
| plannedHousingCapacity | 全部计划居民容纳量 | 当前入住人口 |
| housingCapacity | 当前可用resident places（人数容量） | 套数、户数 |
| actualResidents / population | 模型已入住居民人数 | 实测人口、居住意愿调查结果 |
| offeredJobs | 企业提供的岗位容量 | 已就业人数 |
| filledJobs | 模型已分配岗位 | 提供岗位加上已填岗位 |
| vacancies | 未填岗位；offered = filled + vacancies | 区域真实失业率 |
| meanSatisfaction | 模型0–100合成指数 | 实测满意率 |
| planned/construction/complete | 对应保存月份的建设状态 | 房屋套数、道路公里数 |
| 空的交通/污染/电力层 | 后端未建模/未提供 | 观测值为零 |

本次检查的离线示例末月为2026-09-01，132个组团/对象，居民容量2,500,000、入住人口1,762,500、提供与已填岗位均624,000、空缺0。以上仅用于复核程序接线，是合成模型结果，不是北都实际统计或预测。
