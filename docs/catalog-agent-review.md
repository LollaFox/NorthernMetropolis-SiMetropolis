## 自动测试

`sandbox/tests/test_policy_catalog.mjs` 当前包含 16 项独立测试，全部通过：

1. 片区、政策编号唯一，标签引用有效。
2. 每个片区只返回自身的具体政策。
3. 可用标签由片区目录推导。
4. 多标签按 AND 匹配；混合不兼容标签不会扩大作用范围。
5. 跨区、跨专题及缺少标签的政策作用域被拒绝。
6. 标签、默认参数等嵌套目录数据不可被表单修改。
7. 口岸和专题历史记录不能使用对方的存储格式恢复。
8. 三个案例保留各自模型、片区和指标单位。
9. 住房、教育模型明确声明假设来源和无法提供的输出。
10. 创建多个专题案例不会修改原 Huanggang 历史。
11. 恢复存储时不能把教育案例绑定成住房的当前案例。
12. 专题存储往返后，月度结果保持一致。
13. 三个案例的 API 初始化设置都带有 `policyId`、`areaId`、`model`、`catalogVersion` 和所选标签。
14. 专题表单草稿只应用到当前案例，使用自定研究窗口；重复 Start 不重复增加版本。
15. 专题界面只允许切换当前政策的案例，并保留各自查看月份。
16. 本地专题保存为 API 设置时先离开专题视图，防止旧状态遮住 API 结果。

这些测试证明目录与数据边界符合当前实现，不证明假设参数符合现实。

## 发现并反馈的问题

本地 Housing / School 场景切换到 API 模式时，旧代码仅在已有 API 结果或地图时调用 `restoreRules()`。首次从本地专题切换时，`analysis-topic` 类和容量叠加可能残留；该类的 CSS 会隐藏 `compact-api-results`，导致 API 结果区域空白。主集成已将当前本地专题加入清理条件，在保存引擎设置时离开旧视图，保留专题历史但移除视觉状态。新增回归测试验证了这一切换。

另两项文案已修复：分析面板的辅助技术标签改为通用政策分析面板，住房标签说明去掉当前模型未提供的 affordability。复查当前 `prepareForm`、`captureDraft`、案例切换、月份切换、导出分流后，没有发现新的阻断问题。

浏览器视觉验收没有在本子任务中执行；不绕过此前的 URL 协议访问策略。主集成应将自动测试结果与浏览器验收范围分别报告。
