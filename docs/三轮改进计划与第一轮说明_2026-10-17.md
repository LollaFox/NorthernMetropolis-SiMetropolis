# 三轮改进计划与第一轮说明

版本：H3-round-1-2026-10-17。依据2026-10-16《前后端产品评估与修改指导》开展原位微调，保留英文界面、白模、现有模型和已保存分析。当前完成第一轮；后续两轮的描述是开发计划，不代表已上线。

## 三轮分工与完成标准

| 轮次 | 状态 | 重点 | 完成判断 |
| --- | --- | --- | --- |
| 第一轮：入口与能力一致 | 已实现并完成自动功能测试；待实际画面与用户验收 | 收敛标签，说明当前模型支持；分开政策本地分析与固定后台脚本；维护历史恢复 | 选政策能进入对应模型；未连接机制不冒充支持；恢复和重开不提交新任务 |
| 第二轮：政策方案进入模型 | 计划，尚未实现 | 将政策、作用区、事件、时间、容量与依据形成带版本的方案；后端校验并生成可审阅的政府脚本差异 | 相同政策版本可复现同一输入；改变政策应改变对应输入；未支持建筑/约束明确返回；确认后才运行 |
| 第三轮：比较、证据与展示验收 | 计划，尚未实现 | 同起点基线/方案比较，字段来源与版本追溯，结果摘要与失败边界；真实用户任务测试；GenAI筛选评估 | 比较口径一致；区分月变化和方案差值；结论有可查来源；模型与人工/关键词基线使用同一测试集 |

第二轮优先做一条完整可展示的政策链，其余案例保持目录与清楚的支持状态。第三轮只展示实际跑出的质量、耗时和成本，不预填准确率、置信度或提升百分比。政府/企业权限、跨设备协作与审计属于进一步试点能力，第一轮没有加入空壳按钮。

## 第一轮的实际变化

| 位置 | 用户可见行为 | 原因与边界 |
| --- | --- | --- |
| 标题与政策标签 | Explore policy scenarios. Inspect the evidence.；Housing supply / School places | 名称与容量模型一致；不承诺可负担性、医疗或照护 |
| 首次进入沙盒 | 保留Local scenario models，选择标签后Start analysis | 避免连接本地后端后自动运行与政策无关的固定脚本 |
| Scope & limits | 底栏一条可展开说明；默认不摊开全文 | 展示机制、单位、来源、未评估内容；结果历史页不再占用这条输入说明空间 |
| Team API | 显示Policy not connected / Server script only，明确选择固定建设脚本用途，再Review server script | 标签、作用区背景和PDF不改写现有政府JSON；用途选择不是行政审批，也不证明政策有效 |
| API test | 明确API test only / Run API test | 合成契约测试不称为政策分析 |
| 外部API | Capabilities unverified | 前端不能仅凭连接成功认定支持某政策；须检查返回审阅 |
| 历史与恢复 | 后端历史继续从Analysis history进入；待恢复任务立即显示Resume analysis | 恢复同一任务，不初始化另一任务；已完成存档不强制新沙盒进入后台模式 |
| PDF | 新建任务仍按当前契约要求附件；已有审阅/已完成结果可直接重开 | 修复每次打开都要求重选文件的问题；没有新增PDF正文解读能力 |

用途选择只针对新的、尚未提交的固定脚本任务；已进入审阅、确认、运行、完成或待恢复的会话继续原流程。切换政策或保存新设置仍可能重置当前客户端会话，不能把创建新设置视为恢复任务；后端已保存历史继续保留。

## 指标范围与口径

- 皇岗本地模型：假设通关目标、信息触达和接驳容量影响旅客人次/日；不推算唯一人数、居民迁入迁出或就业。
- 住房本地模型：假设投用时间、供给释放与家庭需求；家庭数和住宅单位分列；没有租金、收入或可负担性结论。
- 学位本地模型：假设学生需求与学位容量；不推算实际录取或医疗照护。
- 后端保存城市：离线合成居民、居民容量、岗位与开发对象；居民容量不是住宅套数，示意对象不是实际项目清单。
- 月份切换继续读取保存状态；上月差值不等于政策因果净效益。

Scope & limits由前端已知适配器生成，是产品能力说明，不是新增的服务器capabilities接口。文本没有动态读取官方资料，也没有提供独立事实核查。原证据筛选只负责保守展示，不认证Agent整段叙事。
