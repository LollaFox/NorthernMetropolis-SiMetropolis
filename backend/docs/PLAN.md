## Defaults selected under user delegation

- 20x20 logical grid, 100 m synthetic cells, embedded into 1000x1000 API raster at 50 pixels per logical cell (2 m synthetic raster scale). Geographic origin uses request bounds but placement is schematic, not surveyed geography; rectangular geographic extent cannot be represented faithfully by one square cell-size field. Explicit review disclosure.
- Default government script: 50 residential towers, 12 business towers, 10 parks, 4 stations, staggered over first 12 monthly steps. Editable local JSON supports alternate locations and dates. One object per logical cell; validate collisions and bounds before runs.
- Four profiles: budget, work, park, stability. Empty initial occupancy; all profiles eligible. 25 residents/group, 4 group slots/tower, at most one group per profile per tower; 100 residents/tower maximum. No finite external population, individual persons, or tracked relocation.
- Monthly role decisions, one call/profile covering eligible towers, with narrative and current 3x3 facts and retained history. Departures before arrivals; rotate role priority each month and then sort tower IDs. Validate whole role response before mutation; conflicting/duplicate actions cannot silently succeed.
- Each group has 15 potential workers. Preserve surviving job assignments and allocate vacancies to unfilled group workers by deterministic nearest workplace, then firm ID. Aggregate worker counts per group/firm; unemployed workers have zero wage and explicit unemployment. Citywide stations reduce distance burden. Group mean commute over employed workers; no employment => null commute. Resident contexts include expected candidate job conditions.
- Small firm: starting funds 1m, monthly profit 50k, GDP 100k, 50 jobs, wage 15k/person/month. Large: 5m, 200k, 400k, 200 jobs, wage 25k. Synthetic HKD units. Firms remain static except accumulated funds and filled vacancies. One immediate firm each completed business tower; invalid AI => explicit deterministic small-firm recovery event, never an empty tower.
- Rent: base 4000/person/month plus 1000/(1+Euclidean logical-cell distance) for each completed firm tower from previous month; recomputed, not accumulated. Nearby completed parks improve quality. Transparent weighted profile satisfaction 0–100 combines affordability, employment/commute, parks, and recent construction; population-weighted overall score, null for no population. AI decides actions using these facts and prose; no numeric-score threshold overrides live decisions.
- Simulations run monthly internally regardless of month/quarter/year output step, with frontend's anchor-day clamping. Default CLI dates 2025-01-01 through 2025-12-01; HTTP honors validated dates.

## Monthly ordering and state

State is JSON: month, config, buildings, resident groups, firm records, role history, narratives, events, metrics. Stable IDs and completion dates. Build order is (completion month, y, x, id). First mark all this month's objects complete; firm decisions see all completed tower shells and prior assigned firms, explicitly distinguish shells. Assign firm then narrate each object in stable order; no station narration. Earlier narratives from same batch are available, later ones are unavailable, never fabricated. Apply current rent from previously qualifying firms. Gather four role decisions against one pre-settlement state. Validate, settle departures, settle arrivals by rotation, allocate jobs, accrue fixed firm profit/GDP, recompute conditions/satisfaction, save immutable monthly state and audit. Next month naturally activates new rent premiums.

## Shared Python interfaces (standard library, Python 3.9+)

Engine owner: backend/engine.py and scenario.py plus tests/test_engine.py. scenario.default_scenario() -> JSON config; validate_scenario(config) -> normalized copy. engine.create_world(config=None) -> dict. engine.advance_month(world, ai, date) -> new dict (no input mutation). engine.assert_invariants(world). ai.call(role, context) -> validated dict, may raise. Roles are narrator, firm, budget, work, park, stability. Engine constructs contexts and records response application outcomes.

AI owner: backend/ai.py, backend/cli.py, tests/test_ai.py. Provider.call(role, context). OfflineProvider is explicitly deterministic fixture, not live AI. OpenAIProvider uses env only on explicit live startup; model defaults gpt-6.1-sol (official model page verified by AI agent), explicit --model override, no persistent configuration. No total call limit. Per-request timeout and bounded retry prevent hung requests (not a call quota). Metrics capture input bytes, latency, status, returned provider usage; no API keys in persisted records. Live schema: narrator {character:string}; firm {firmType:'small'|'large',reason:string}; residents {actions:[{towerId:string,action:'move_in'|'leave',reason:string}],reason:string}. No AI numeric quantities. Social character clearly attributed synthetic prose, canonical numerical facts owned by code.

API owner: backend/service.py, server.py, snapshots.py, tests/test_service.py and contract bridge. service uses create_world/advance_month and provider factory. Async simulation workers and durable states/jobs/idempotency. Local HTTP routes matching actual frontend client; server must support /api/v3 aliases if used to serve unchanged frontend, preserve legacy APIs via existing server adapter where practical. CLI python3 -m backend.server. Backend state saved beneath explicit data directory, default backend/.data; do not commit runtime data.
